# WHY THE ADMIN RULE IS A WILDCARD
#
# "Disallow: /*/admin" covers the admin console for every crawler — including
# any sub-path, since an unanchored robots.txt pattern matches by prefix — WITHOUT
# spelling out the route's obscure first segment. This file is world-readable and
# is the first thing an automated scanner fetches, precisely to harvest admin
# paths, so writing the literal URL here would hand it over for free.
#
# A previous version did name it, with a typo ("-admin" instead of "/admin"), so
# the pattern matched nothing at all and the console was disallowed for no
# crawler whatsoever. The wildcard cannot drift that way: it matches the shape of
# the route rather than one hand-copied spelling.
#
# Robots.txt is only the crawler half. It is advisory and stops no attacker. The
# console is defended by, in order of what actually matters:
#   1. Server-side authorisation. All 11 admin RPCs are SECURITY DEFINER and
#      raise 'Access Denied' unless the caller's JWT email is on an allow-list,
#      so an unauthenticated visitor who reaches the URL gets an empty shell.
#   2. A noindex robots meta tag in the FIRST BYTE of the response, so crawlers
#      that ignore robots.txt still will not index it, and crawlers that do not
#      run JavaScript see it too. See NOINDEX_ROUTES in scripts/prerender.mjs.
#   3. An X-Robots-Tag response header set in vercel.json, which applies even to
#      clients that never read this file.
#
# Do not add private routes here by name. Add them to NOINDEX_ROUTES instead.
